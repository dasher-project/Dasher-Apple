- [ ] **Input system overhaul — device + filter presets per platform** — Currently only "Stylus" is shown as a single setting. The original Dasher v5 had a two-part architecture: **Input Device** (`SP_INPUT_DEVICE`) provides raw coordinates, **Input Filter** (`SP_INPUT_FILTER`) interprets them. The v5 iPhone app paired them into user-friendly presets via `InputMethodSelector.mm` (3 sections: Normal Steering, Box Modes, Dynamic Modes). We need to recreate this for v6 with modern iOS/macOS/visionOS input capabilities.

  ### Background: DasherCore Architecture
  DasherCore already has this split built in. `CreateModules()` in `DasherInterfaceBase.cpp:700` registers 15+ filters. The engine doesn't need changes — we need platform-specific `CDasherInput` subclasses and a preset selector UI.

  ### Original v5 iPhone Inputs (from `../dasher/Src/iPhone/Classes/`)
  - **Touch Input** (`TOUCH_INPUT` = "Mouse Input", Module 9) — standard touch with optional X-axis doubling for full-screen control. `CIPhoneMouseInput` in `IPhoneInputs.mm`.
  - **Undoubled Touch** (Module 7) — raw touch, no doubling. `UndoubledTouch`.
  - **Tilt Input** (`TILT_INPUT` = "Tilt Input", Module 8) — `CIPhoneTiltInput` used `UIAccelerometer` (deprecated iOS 5) with median filter (SBTree), orientation-aware axis mapping, Vec3 dot product for main/slow axes. Had calibration UI (`CalibrationController`). **Needs rewriting with `CMMotionManager` (CoreMotion)**, but the math is directly reusable from `IPhoneInputs.mm:114-142`.
  - **Two-finger Input** (`TWO_FINGER_INPUT`, Module 10) — midpoint Y of two touches, distance between fingers = speed, 3+ fingers = reverse. `CIPhoneTwoFingerInput` in `IPhoneInputs.mm:216-238`.

  ### Original v5 iPhone Filters (from `IPhoneFilters.h`)

  - **Tilt Filter** — `COneDimensionalFilter` subclass, hold-to-go support, optional touch for X-axis, 1D mode

  ### visionOS: Hand Point + Finger Switches
  Use one hand to point (position feeds `dasher_mouse_move()` as the Dasher crosshair), and individual finger gestures on the other hand as discrete switch inputs (feed `dasher_key_event()`). This gives a hands-free two-switch setup without any hardware.

  **How it would work**:
  - **Pointer hand**: Track palm/fingertip position in 3D space using ARKit hand tracking (`HandTrackingProvider` from `ARKit`). Map the hand's projected screen position to Dasher coordinates — the crosshair follows where you point.
  - **Switch hand**: Detect specific finger pinches via ARKit as switch events:
    - Thumb + index pinch = switch 1 (key 1) → e.g. "go" / select
    - Thumb + middle pinch = switch 2 (key 2) → e.g. "reverse" / deselect
    - Thumb + ring pinch = switch 3 (key 3) → optional third action
    - Open hand (all fingers extended) = pause / start-stop (key 0)
  - Pair with appropriate filter: One-button Dynamic (1 switch), Two-button Dynamic (2 switches), or Two-push Dynamic (2 switches, different timing)

  **Implementation**:
  1. Use `ARKit.HandTrackingProvider` to get `HandAnchor` updates each frame (already available on visionOS, no extra permissions beyond standard hand tracking entitlement)
  2. Map pointer hand: project `HandAnchor.originFromAnchorTransform` to 2D screen coordinates relative to the Dasher window. Feed to `dasher_mouse_move()`
  3. Map switch hand: detect pinch gestures from `HandAnchor.handSkeleton?.joint(.thumbTip)` proximity to other fingertip joints. Debounce (min 200ms between events). Feed to `dasher_key_event(key, pressed)`
  4. Add UI to configure which hand is pointer vs. switch, and which fingers map to which keys
  5. Add visual feedback: show hand skeleton overlay or indicator dot on the Dasher canvas so user sees where they're pointing

  **Why this matters**: This is the most accessible visionOS input — no hardware needed, no precise eye tracking, uses natural hand gestures. Two-switch dynamic mode with hand pointing could be very efficient for experienced users.

  **Reference**: ARKit hand tracking docs — `HandTrackingProvider`, `HandAnchor`, `HandSkeleton`. visionOS apps get hand tracking data at up to 30fps without any special entitlement beyond `com.apple.developer.arkit.hand-tracking`.

  ### Implementation Steps
  1. Create `InputMethodPreset` struct in Swift: `{ name, subtitle, deviceName, filterName, platform: [.iOS, .macOS, .visionOS], icon }`
  2. Build `InputMethodSelectorView` (SwiftUI) — grouped list like v5's 3 sections, with checkmark for active
  3. Create `CMMotionManager`-based tilt input (Swift, bridges to `dasher_mouse_move()`) — reuse median filter math from `IPhoneInputs.mm`
  4. Add calibration UI for tilt (SwiftUI view that records neutral position, main axis, slow axis)
  5. Map iOS pointer events (iPad Pro eye tracking) — may already work if pointer events feed `dasher_mouse_move()`
  6. Test switch access — verify iOS Switch Control sends key events that reach `dasher_key_event()`
  7. Add GameController framework support for macOS joystick/gamepad
  8. Wire preset selection to `SP_INPUT_DEVICE` + `SP_INPUT_FILTER` via bridge
